# 表情を記録する実験版

既存の改善作業から分けたローカル実験です。Unityの準備後コピーで作った顔を、
基準の顔との差分BlendShapeとして保存します。原本のアバター、メッシュ、Controllerを変更しません。
通常の書き出し画面は変更していません。

## 導入

1. Unity 2022.3とlilToon 2.3.4、UniGLTF／UniVRM 0.131.xがある実験用プロジェクトを使います。
   Modular Avatarを使うアバターではMAとNDMFも導入します。
2. 実験版ZIPを展開し、中の`package.json`をPackage Managerの「Add package from disk」で指定します。
   ローカルの作業コピーからも同じ方法で導入できます。安定版Exporterを重複導入せず、通常のプロジェクトとは分けて試してください。
3. **VR Vlog → 実験 → 表情を記録して書き出す** を開きます。

## 記録と書き出し

1. 表示中のアバターを指定し、作者名を入力して「記録用コピーを作成」を押します。
   「ライセンス設定」は通常版と同じ欄です。元の規約に合わせて設定でき、指定した規約URLなども出力へ反映します。
   MA／NDMFの組み立て後の顔が最初の基準です。VRChat起動後の無表情と一致するとは限りません。
2. 必要ならメッシュと変形量を調整し、「今の顔を基準にする」を押します。
3. 「既存の表情候補を読み込む」から既存の取り込み処理が評価できた候補を選び、プレビューします。
   取得不可の理由も表示します。動く候補は「記録する時刻」を選び、静止した一枚の顔として使えます。
4. 自動取得できない顔も、メッシュを選んでBlendShapeの変形量を調整できます。
   複数メッシュを順に調整して一つの表情へまとめられます。
5. 表情名を入力して「今の顔を記録」を押します。「基準の顔に戻す」から次の表情を作ります。
   同じ名前は重複登録できません。最大64件です。基準を後で変更すると保存時の差分を再計算します。
6. 「記録設定を保存」でJSONを保存します。ウィンドウを閉じる・スクリプトを再読み込みする前に保存してください。
   同じ準備後メッシュの構成と形状なら、コピーを作り直しても設定を読み込めます。
   メッシュの形状や変形定義が変わった設定は、誤適用せず拒否します。
7. 「記録した表情をlilToon VRMへ書き出す」で保存します。
   瞬きの自動設定ができない場合は「瞬きを自動設定する」をOFFにして試せます。この場合、自動瞬きは追加しません。
   既存アプリの固定表情経路を使うため、カスタム表情名は **VRChat / 記録 / 表情名** です。
   ON／OFFで切り替える固定表情です。実験書き出しのカスタム表情は、今回記録した顔から作ります。
   選択中は既存の固定表情と同じく、瞬き・口パク・視線の追加を抑制します。

## 範囲と検証

対象は、表示中のSkinnedMeshRendererの同じメッシュにあるBlendShapeによる固定形状です。
材質や画像の差し替え、涙などの表示切り替え、顔ボーン、連続Puppet、VRChatの外部入力の再生は追加していません。
元アバターが編集中に変わった場合は、古い結果で書き出さずコピーの作り直しを案内します。
保存失敗時は既存のファイルを保持し、一時ファイルを回収します。

検証では、生成した公開可能な合成アバターを実際にVRMへ書き出して再読込し、
元と異なる初期値からの表情、複数メッシュ、表情解除後の基準復帰、原本不変、
設定の再読込と不正な設定の拒否を確認します。私有アバターやVR Vlog実機での受入は別です。

この実験版はローカルで試すための作業コピーです。安定版・ALCOM一覧へは公開していません。
