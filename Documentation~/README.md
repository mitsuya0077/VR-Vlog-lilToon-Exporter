# VR Vlog lilToon VRM Exporter

**0.11.15-beta.2** は、表情・ポーズのファイルを指定してプレビューし、VRMを保存するベータ版です。ALCOMの **Show pre-release packages** を有効にして選択します。保存後は **QRコードでスマホに送る** から、QR受信に対応するiPhone版VR Vlogへ転送できます。プライバシーポリシーへのリンクと保存される同意チェックを備え、同意済みでもボタンを押すまで送信しません。[QR転送ガイド](CloudTransfer.md)を参照してください。

NDMFに通知があると `The scene is invalid.` で書き出しが止まる問題を修正しています。元のアバターを保持し、実際のエラーは引き続き表示して停止します。ライセンス設定は従来どおり出力VRMに保存します。

## 従来の安定版

正式版 **0.11.14** は、書き出し詳細とエラーの全文コピー・テキスト保存に対応した **VRM書き出し専用版** です。表情に使うパラメーターを初期値と同じ値へ戻すだけの追加Playableによって、書き出しが止まる問題の修正も含みます。全ての書き込み元と初期値のメタデータを検査し、値を変えないSDKのSet処理や、独立した通常入力で到達しない書き込みだけを扱います。QR転送の実装と転送ガイドは安定版の配布パッケージに含めません。QR転送を使う場合は本書の **0.11.15-beta.2** の案内を参照してください。

0.11.14では、LocomotionなどFX以外のPlayable LayerとFXが同じBlendShapeを使う場合に、初期表情の確定で書き出しが止まる問題を修正しました。影響する表情のまとまりは書き出し用コピーの現在の設定を保持し、対象と理由を警告に表示します。独立した初期表情は引き続き評価し、元のアバターやControllerは変更しません。

VCC／ALCOMのパッケージ一覧から **0.11.14** を選択してください。ALCOMの **Show pre-release packages** 設定を有効にする必要はありません。書き出したVRMは端末の「ファイル」に保存して、VR Vlogから読み込みます。

0.11.13以降では書き出し詳細とエラー画面の **全文をコピー** ・ **テキスト保存** から、工程・対象・理由・対処・影響と例外全文を省略せず取り出せます。内部例外・スタックトレースを含み、コピーとUTF-8の.txtファイルは同じ内容です。全文にはアバター名やパスを含むため、公開前に内容を確認してください。共有用の診断コピーも引き続き利用できます。

0.11.10以降では、標準VRM表示・lilToon専用表示の画像を縦横比を保って最大1024×1024へ縮小します。小さい画像は拡大しません。元アバターや画像の設定は変更せず、縮小した画像を結果に表示します。高解像度画像によるメモリ負荷を減らすには、更新後に元アバターからVRMを書き出し直してください。

lilToonのアバターを、iPhoneのVR Vlogで使うVRM 1.0に書き出すUnity用パッケージです。

PhysBoneの重複は元の静止姿勢を残して担当を分け、左右別メッシュの瞬きや最適化後の空メッシュも扱います。揺れ方はVRM向けの近似となる場合があります。[保持する内容と検証方針](https://github.com/mitsuya0077/VR-Vlog-lilToon-Exporter/blob/v0.11.14/Compatibility/AvatarPreservation.md)を確認してください。

## 必要な環境

Unity 2022.3、lilToon **2.3.4**、UniVRM **0.131.0／0.131.1／0.131.2**、VR Vlog **0.1.1（ビルド345）以降**が必要です。VCC・ALCOMではUniVRM 0.131.xを自動で導入し、対応版か確認します。Modular Avatarを使う場合は、その依存パッケージも事前に導入してください。

## 使い方

以下は0.11.15-beta.2で採用した操作です。公開済み0.11.14や0.11.15-beta.1のZIPは変更していません。

1. Unityでアバターと書き出す衣装を表示します。
2. **VR Vlog → VRMを書き出す** を開き、アバターを指定して **書き出しを準備** を押します。
3. 必要な表情ファイルを複数選択して追加し、名前や **確認** でプレビューします。.animの複数ドロップも使えます。表情を追加しなくても保存できます。
4. 任意の全身ポーズ・作者名・ライセンス設定を確認し、**VRMを保存** を押します。
5. 保存完了欄の **QRコードでスマホに送る** を開き、プライバシーポリシーを確認して同意にチェックを入れ、**アップロードしてQRを表示** を押します。QR受信対応のiPhone版VR Vlogの **モデルを変更 → PCから受け取る** で読み取ります。ファイルで送る場合は **モデルを変更 → 端末のVRMを選ぶ** から読み込めます。VR Vlogで **lilToon専用表示** をオンにしてください。

操作と対応範囲は同梱の[VRM書き出しガイド](ExperimentalExpressionCapture.md)を参照してください。成功すると画面内に保存結果を表示します。**保存先を開く** でファイルを確認できます。

**ライセンス設定** は保存欄にあります。元の利用規約に合わせて利用者・商用利用・クレジット表記・表現用途・再配布・改変をプルダウンで選び、必要に応じて規約URL（VN3等）・著作権表示・第三者ライセンスを入力してください。条件は出力VRMのメタデータに保存されます。設定を開かない場合は従来の既定値で書き出せます。追加の確認画面はありません。

## 公開済み従来版の自動取り込み

0.11.0以降では、APL登録やVRChat/Modular Avatarメニューから静止姿勢を確定できるポーズを自動で同梱します。**ポーズを確認・調整** で除外・名前変更・プレビューや、未登録.animの手動追加と採用時刻の指定ができます。利用には静止ポーズ対応版のVR Vlogが必要です。元のUnityアバターから再出力し、アプリの **ポーズ** から選択してください。0.11.11-beta.12 では手動追加した動く .anim の開始時刻以降をアニメーションとして保存し、元クリップのループ設定も引き継ぎます。動くポーズは対応する読み込み・再生処理を備えた VR Vlog が必要です。複雑な合成、外部入力や履歴に依存する姿勢は対象外です。[動くポーズの仕様](HumanoidAnimations.md)を参照してください。[対応範囲の詳細](https://github.com/mitsuya0077/VR-Vlog-lilToon-Exporter/blob/v0.11.0/Documentation~/HumanoidPoses.md)を確認してください。

0.10.6以降では、導入済みVRChat SDKのPhysBoneから髪・衣装の揺れ設定を引き継ぎます。力・減衰・重力は近似で、件数や未対応項目は書き出し結果の **書き出しの詳細** で確認できます。SDKは必須ではありません。揺れ設定がない既存VRMは、元のUnityモデルから書き出し直してください。

表情メニューは、各項目を既定状態から選んだ結果を同じ名前で登録します。Parameter DriverのSet・Add・Copyに対応しますが、操作履歴・Random・外部入力に依存する結果は移植しません。元モデルと前処理後のモデルの両方にないBlendShape参照は、その参照だけ省略して名前を報告します。

他のレイヤーへ影響しないことを確認できるRandomの待機アニメーションは、基準形を決める際に途中の値を焼き込まず、書き出し用コピーのBlendShape設定を保持します。Randomの動作そのものや、それに依存するメニュー表情を再現する機能ではありません。上位レイヤーの常時設定を保持できない場合や、他の処理への影響を確認できない場合は診断を表示します。

時間による状態遷移、未取得の外部入力、未対応の見た目の曲線でFXの初期状態を固定できない変形は、書き出し用コピーの設定を保持して続行します。独立した開眼・体形などの常時設定は引き続き基準形に保存します。保持した対象と理由は **書き出しの詳細** に表示します。保持した部分はVRChat起動後の見た目と異なる場合があります。参照の不整合、不正な値、未知の処理、必要な瞬き・追跡表情の欠落などは引き続き停止の対象です。

追跡設定コンポーネントがあるアバターには、ARKit標準名52項目を実際のモーフへ結び付けて書き出します。この明示的な設定を優先します。設定がない場合も、UE の既知のシェイプ名があれば以下の自動検出を利用できます。Kipfel用のPrefabと初期設定は別配布の顔トラッキングアドオンから導入し、各表情の強さを調整してください。

0.11.5以降では、追跡設定がない場合も Unified Expressions の既知のシェイプ名を自動検出し、`UE/<項目名>` の連続値カスタム表情を登録します。部分的な対応や複数の顔メッシュも扱い、元の顔・体形の調整と VRM の手動設定を保持します。ARKit と共通の名前だけでは Unified Expressions と判定しません。名前が重複するあいまいな割り当ては結果に表示して省略します。左右の閉眼が別メッシュにあっても標準の瞬きを登録します。片目だけの場合は利用できる UE 項目を保持し、両目の瞬きは自動生成しません。既存の UE 設定は変形・マテリアル色・テクスチャ変換を含めて優先し、0% の設定も自動で置き換えません。空の設定だけは補完し、不正な参照は診断を表示して保持します。利用には対応版の VR Vlog が必要です。UE の追跡用モーフが残っている既存のローカル VRM はアプリで補完できます。モーフが失われている場合や新しい設定を出力する場合は、元アバターから再書き出してください。反映できる動きは iPhone が取得できる範囲です。未取得の舌の向き・頬吸いなどの信号や、VRChat の Animator だけで実現するギミック全体は再現しません。

パッケージが不足・未対応の場合は **VR Vlog → 動作環境を確認** で現在の版と対処方法を確認できます。パッケージを自動で変更することはありません。

対応版が入っているのに書き出し画面が開かない場合は、同画面の **再読み込み** を押し、Unityのコンパイル完了を待ってください。直らない場合は **診断情報をコピー** の内容を不具合報告に添えてください。

元のアバターは変更しません。更新内容を反映するには元アバターから再書き出ししてください。すべてのシェーダー効果やVRChatの動作を再現するものではありません。

Modular Avatarの **Shape Changer（Delete）** と **Mesh Cutter** によるメッシュ削除は、NDMF／MAのプレビュー表示のオン・オフにかかわらず反映します。体形・材質・表示切り替えも、MAが解決した設定を使い、シミュレーターで選んだ表示を引き継ぎます。更新後に元アバターからVRMを書き出し直し、通常状態・瞬き・表情でも削除箇所や常時設定が維持されることを確認してください。

Avatar Optimizerの **AAO Remove Mesh By Box** を設定した衣装・身体メッシュは、範囲内／範囲外の指定と回転した複数のBoxを含めて削除結果を書き出します。範囲内を削除する設定では、頂点すべてがBoxの範囲に入るポリゴンが削除され、一部だけ入るポリゴンは残ります。通常のBoxColliderを置くだけでは、この削除設定になりません。AAOのプレビューで範囲を確認し、更新後に元アバターからVRMを書き出し直して、通常状態・瞬き・口・表情で貫通箇所が戻らないことを確認してください。Avatar Optimizerは任意依存で、対応する1.7以上・2.0未満の版が必要です。

AAO 1.9.20本体の頂点バッファ解放漏れは、[同版用の修正手順](DependencyPatches/README.md)で扱います。パッケージのコピーへ版とソースを照合したパッチを明示的に適用し、「1.9.20 + 修正パッチ」として検証してください。パッチ・適用ツール・元のライセンスを同梱しています。エクスポーターは依存パッケージを自動変更しません。

## 書き出しが止まったとき

エラー画面で工程・対象・原因・対策・失われる効果を確認してください。根拠のある候補が表示された場合は、試す対策を選んで再試行します。AudioLinkをOFF、メインカラー2nd／3rdレイヤーの省略、代替表示で隠す指定のある補助Rendererの除外に対応します。未知の仕組みや名前だけから除外を勧めることはありません。

VRChatメニューの取り込み候補が上限を超える場合は、対象の範囲と候補件数を表示します。**このメニューの枝を取り込まない** を必要な範囲で選ぶか、**VRChatメニュー由来の表情・ポーズをすべて取り込まない** を選び、コピーで再試行してください。枝は複数選択できます。メニューの分割だけでは全体の合計項目数は減りません。同じサブメニューを別経路から参照する場合も、表示された経路ごとに範囲を選びます。全省略と枝の省略を同時に選んだ場合は全省略を優先します。

メニューの省略は、その範囲に由来する表情・静止ポーズの取り込みを減らす操作です。衣装・髪・骨格のオブジェクト自体は削除せず、元のメニューアセットも変更しません。静止画像では、取り込まれなくなった表情・ポーズは確認できません。プレビュー画面の **取り込まない表情・ポーズ** に表示された対象と変更点も確認してから保存してください。

対策は毎回新しいコピーに適用し、元アバターと共有マテリアルを変更しません。同じ材質を使う箇所すべてに対策が反映されるため、プレビューで衣装・髪・模様・透明度も確認してください。保存するVRMのモデル・画像・材質設定を読み込み、lilToonで表示します。照明や端末の描画環境によって、VR Vlogでの見え方は異なる場合があります。

Aim・Rotation Constraintが有効かつロックされ、回転の全軸を完全に制御している場合は、Editorが計算した回転の更新だけで前の結果を無効にしません。部分的に回転を制御するVRChat Constraintでは、最初に記録した回転を基準として、ごく小さな計算誤差だけを許容します。繰り返し確認しても比較の基準は移動しません。Constraintの設定、参照元、外部の追従先、Prefabの関連付け、材質やメッシュなどを変更した場合は再検査が必要です。

対策を選んで書き出せた場合は、**書き出すVRM** でlilToonの見た目を確認してから保存します。設定を変えずに再試行して成功した場合は自動保存し、保存先にファイルがあれば上書きを再確認します。上書きを断ると保存しません。再試行に失敗しても直前の成功結果と保存済みVRMは残ります。対策の選択を解除すると元の設定を使い、原本や参照アセットが変わった場合は再検査が必要です。共有用診断のコピーには、個別アバター名や材質名、絶対パス、画像、元のスタックトレースを含めません。

### メインカラー2nd／3rdの色空間

lilToon専用表示のレイヤー合成には、書き出し元のUnityプロジェクトの色空間も必要です。Exporterは`asset.extras.VRVLOG_lilToonColorSpace`に`linear`または`gamma`を保存します。色・画像・alpha・マスク・UVの値は変更せず、既存のschema 2.0とMToon標準表示を維持します。

対応するVR Vlogでは、Linearで作った2nd／3rdの重ね合わせをGammaのアプリでもLinearで計算します。出力元の情報がない旧VRMはVRChatのLinearワークフローを前提に読み込みます。旧ExporterでGammaプロジェクトから書き出したVRMは、対応版のExporterで書き出し直す必要があります。透明材質を背景に合成する工程や照明全体をLinearへ変更する修正ではありません。
