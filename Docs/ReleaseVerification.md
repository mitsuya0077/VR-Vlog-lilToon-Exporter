# 0.8.1 正式版の検証と配布

0.8.1 は手動のボーン指定画面を廃止し、MAの設定済みの接続をそのまま使って書き出します。0.8.0で対応したschema 1.2とLightLimitChangerの一時アセット保存先は維持します。更新後は元の Unity アバターから VRM を書き出し直します。すでに書き出した VRM には、元の Merge Armature / Bone Proxy の設定が残っているとは限りません。

## ホストで実行する検証

最新の PR コミットをレビューし、Validate と VPM リスト生成テストを通します。コードを変更した場合は、影響する検証と最新コミットのレビューをやり直します。

- `python3 Tools/validate.py`: バージョン、スキーマ、書き出し処理の順序、テストアセンブリ参照を確認します。
- `Tools/run-behavior-tests.ps1`: JSON・数値処理に加え、画像の色／数値チャンネル別の縮小、GLB 内の画像置換と共有参照、スキンの共通祖先補正を実行します。画像コーデックのテストダブルは Unity の PNG/JPEG 処理の代用とは扱いません。
- `Tools/run-bake-tests.ps1`: 実際のマテリアル事前判定と、同意を得たレイヤー省略処理をテストダブルで実行します。
- `Tools/run-ndmf-preparation-tests.ps1`: 実際の準備クラスと Editor テストを使い、API 契約、共有アセットの分離、失敗時の解放、表情の残存を検証します。実際の Modular Avatar パイプラインを使うケースはホストでは明示的にスキップします。

実行結果には対象コミットと依存バージョンを記録します。ホストテストだけで、Unity 全体のコンパイル、GPU の色空間、ALCOM の操作、iPhone の描画を確認済みとは扱えません。

## Unity・アプリで確認する項目

ローカルの Unity 2022.3.22f1、UniVRM 0.131.0、lilToon 2.3.4 と、対応する NDMF 1.x / Modular Avatar を使用します。`Tests/Editor` と、Gamma / Linear に依存する材質・画像のテストを実行し、NUnit XML と Editor ログを保存します。GPU ベイクを含むため `-nographics` は使用しません。エクスポーター検証のための有料 Cloud ビルドは不要です。LightLimitChanger 1.14.4 はエディターの GUI 初期化を必要とするため、実モデルの書き出しは通常の Editor から行います。

1. 別の骨格を持つ衣装に Merge Armature を設定し、準備後に身体の腕を動かすと袖が追従することを確認します。Bone Proxy、入れ子の衣装、FaceEmo の合成表情も確認します。元の階層、ボーン参照、未保存メッシュ・マテリアル・設定アセットを比較します。
2. 4K のメイン画像、法線、バックライト、アウトライン、色と数値用途で共有する画像を出力します。長辺 1024 以下、縦横比保持、元画像のインポート設定が不変であることを確認します。
3. Root Bone が AutoAnchorObject のメッシュで、全頂点にウェイトがない場合と、アバタールートをボーンに含む場合を比較します。変換前後の位置・法線・接線・BlendShape、メッシュオブジェクトやアンカーを動かした際の追従を確認します。一部の頂点だけにウェイトがないメッシュは、Unity 上でその頂点が潰れて逆変換できないため、対象名と修正理由を表示して停止することを確認します。
4. 新しく出力した VRM をアプリで読み込み、頭・腕を動かしたときの衣装と髪の追従、装飾の位置、目の色、登録済み表情を比較します。
5. 不対応のマテリアル設定の説明、同意を得たコピー側だけの省略、除外対象、`.vrm` 以外への保存拒否について既存の回帰テストを確認します。
6. MA Bone Proxy付きの髪をアバター直下に置き、通常のワンクリック書き出し後にVRMを再読み込みして、ControlRigの頭へ全メッシュが追従することを確認します。独立したペットが共存しても確認画面を出さず、その接続は変更しません。元のアバター・メッシュ・共有リグが不変であることも確認します。
7. LightLimitChanger がある構成で、NDMF 実行から VRM 保存までアセットの参照が生存し、一時ディレクトリが成功・失敗の両方で片付くことを確認します。元のアセットと隣接ディレクトリは不変とします。
8. 同じ照明で lilToon と対応アプリを比較し、照明上限・下限、影の方向、発光、リム、MatCap、バックライトを単独と組み合わせで確認します。schema 1.0/1.1 の既存 VRM、schema 1.2 の再出力、拡張のない VRM、透明・輪郭・表情の色変更を含めます。
9. 標準体型・低頭身・不正な目ボーン・ペット付きで、初回表示、顔検出、横向き、未検出と再検出、回転、小窓、保存動画を確認します。症状のあるテスターモデルの解消判定はテスターの実機で行います。

## ALCOM 向けの公開

対応するアプリをTestFlightへ配布し、エクスポーターのローカル検証を完了してから公開します。照明・表示距離・表情についてテスターの実機でのみ判定できる症状は、確認待ちとして配布結果と区別して記録します。レビュー済み PR を main へマージします。GitHub Actions の **Release VPM Packages** を main から実行し、Exporter `0.8.1` / UniVRM `0.131.0` を指定します。ワークフローはバージョン、ホストテスト、タグ重複を確認し、パッケージを添付した `v0.8.1` リリースを作成します。その後 VPM リスト生成・GitHub Pages 配備が実行されます。

公開後、次を照合します。

- エクスポーター ZIP の `package.json` が `0.8.1` で、内容がレビューしたコミットと一致する。
- [VPM リポジトリ](https://mitsuya0077.github.io/VR-Vlog-lilToon-Exporter/index.json) に `0.8.1` があり、添付 ZIP の URL と SHA-256 が一致する。
- 同梱の UniVRM パッケージが固定バージョンと一致する。
- ALCOM のリポジトリ更新と既存プロジェクトへの更新、新規プロジェクトへの導入を確認する。

私有アバター、参考画像、元 Unity プロジェクト、アプリの非公開コードをリリースへ添付しないでください。
