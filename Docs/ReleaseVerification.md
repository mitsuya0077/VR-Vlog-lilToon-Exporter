# 0.7.4 正式版の検証と配布

0.7.4 は、Modular Avatar の衣装・髪の追従設定の適用、大きな画像の自動縮小、AutoAnchorObject などを Root Bone に使うメッシュの配置保持を追加します。更新後は元の Unity アバターから VRM を書き出し直します。すでに書き出した VRM には、元の Merge Armature / Bone Proxy の設定が残っているとは限りません。

## ホストで実行する検証

最新の PR コミットをレビューし、Validate と VPM リスト生成テストを通します。コードを変更した場合は、影響する検証と最新コミットのレビューをやり直します。

- `python3 Tools/validate.py`: バージョン、スキーマ、書き出し処理の順序、テストアセンブリ参照を確認します。
- `Tools/run-behavior-tests.ps1`: JSON・数値処理に加え、画像の色／数値チャンネル別の縮小、GLB 内の画像置換と共有参照、スキンの共通祖先補正を実行します。画像コーデックのテストダブルは Unity の PNG/JPEG 処理の代用とは扱いません。
- `Tools/run-bake-tests.ps1`: 実際のマテリアル事前判定と、同意を得たレイヤー省略処理をテストダブルで実行します。
- `Tools/run-ndmf-preparation-tests.ps1`: 実際の準備クラスと Editor テストを使い、API 契約、共有アセットの分離、失敗時の解放、表情の残存を検証します。実際の Modular Avatar パイプラインを使うケースはホストでは明示的にスキップします。

実行結果には対象コミットと依存バージョンを記録します。ホストテストだけで、Unity 全体のコンパイル、GPU の色空間、ALCOM の操作、iPhone の描画を確認済みとは扱えません。

## Unity・アプリで確認する項目

Unity 2022.3.62f3、UniVRM 0.131.0、lilToon 2.3.4 と、対応する NDMF 1.x / Modular Avatar を使用します。`Tests/Editor` は Gamma / Linear の両方で実行し、NUnit XML と Editor ログを保存します。GPU ベイクを含むため `-nographics` は使用しません。

1. 別の骨格を持つ衣装に Merge Armature を設定し、準備後に身体の腕を動かすと袖が追従することを確認します。Bone Proxy、入れ子の衣装、FaceEmo の合成表情も確認します。元の階層、ボーン参照、未保存メッシュ・マテリアル・設定アセットを比較します。
2. 4K のメイン画像、法線、バックライト、アウトライン、色と数値用途で共有する画像を出力します。長辺 1024 以下、縦横比保持、元画像のインポート設定が不変であることを確認します。
3. Root Bone が AutoAnchorObject のメッシュで、ウェイトのない頂点、ウェイトありとの混在、アバタールートをボーンに含む場合を比較します。変換前後の位置・法線・接線・BlendShape、ボーンやアンカーを動かした際の追従を確認します。
4. 新しく出力した VRM をアプリで読み込み、頭・腕を動かしたときの衣装と髪の追従、装飾の位置、目の色、登録済み表情を比較します。
5. 不対応のマテリアル設定の説明、同意を得たコピー側だけの省略、除外対象、`.vrm` 以外への保存拒否について既存の回帰テストを確認します。

## ALCOM 向けの公開

レビュー済み PR を main へマージします。GitHub Actions の **Release VPM Packages** を main から実行し、Exporter `0.7.4` / UniVRM `0.131.0` を指定します。ワークフローはバージョン、ホストテスト、タグ重複を確認し、パッケージを添付した `v0.7.4` リリースを作成します。その後 VPM リスト生成・GitHub Pages 配備が実行されます。

公開後、次を照合します。

- エクスポーター ZIP の `package.json` が `0.7.4` で、内容がレビューしたコミットと一致する。
- [VPM リポジトリ](https://mitsuya0077.github.io/VR-Vlog-lilToon-Exporter/index.json) に `0.7.4` があり、添付 ZIP の URL と SHA-256 が一致する。
- 同梱の UniVRM パッケージが固定バージョンと一致する。
- ALCOM のリポジトリ更新と既存プロジェクトへの更新、新規プロジェクトへの導入を確認する。

私有アバター、参考画像、元 Unity プロジェクト、アプリの非公開コードをリリースへ添付しないでください。
