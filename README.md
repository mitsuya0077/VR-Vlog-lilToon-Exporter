# VR Vlog lilToon VRM Exporter

**お気に入りのアバターをVR Vlogで使う。**

lilToonのアバターを、iPhoneのVR Vlogで使う **VRM 1.0** に書き出すUnity用パッケージです。

[インストールページ](https://mitsuya0077.github.io/VR-Vlog-lilToon-Exporter/) · [最新リリース](https://github.com/mitsuya0077/VR-Vlog-lilToon-Exporter/releases/latest) · [変更履歴](CHANGELOG.md)

## 必要な環境

| 項目 | 条件 |
| --- | --- |
| Unity | 2022.3。VRChatプロジェクトではVCC・ALCOMが案内する対応版 |
| lilToon | **2.3.4**。アバターと一緒に事前に導入 |
| UniVRM | **0.131.0／0.131.1／0.131.2**。VCC・ALCOMでは0.131.xを自動導入し、対応版か確認 |
| VR Vlog | **0.1.1（ビルド345）以降** |

Modular Avatarを使うアバターは、Modular Avatarとその依存パッケージも事前に導入してください。

## インストール

1. [インストールページ](https://mitsuya0077.github.io/VR-Vlog-lilToon-Exporter/)で **VCC / ALCOMに追加** を押します。
2. VCC・ALCOMで使いたいUnityプロジェクトのパッケージ管理画面を開きます。
3. **VR Vlog lilToon VRM Exporter** をインストールします。

ボタンで開かない場合は、リポジトリ追加画面に次のURLを貼り付けてください。

```text
https://mitsuya0077.github.io/VR-Vlog-lilToon-Exporter/index.json
```

更新するときはUnityプロジェクトをバックアップし、パッケージ一覧を更新して最新版を適用します。変更を反映するには、元のアバターからVRMを書き出し直してください。

### ZIPで手動導入する

1. [インストールページ](https://mitsuya0077.github.io/VR-Vlog-lilToon-Exporter/)の **ZIPで導入** から、エクスポーター・UniGLTF・VRMの3つのZIPをダウンロードします。
2. プロジェクトの `Packages` 内の別々のフォルダーへ展開し、それぞれの直下に `package.json` がある状態にします。
3. Unityで読み込みが終わるのを待ちます。同じUniVRMパッケージを重複して導入しないでください。

## 使い方

1. Unityでアバターを開き、書き出す衣装を表示します。アバターと親オブジェクトも有効にしてください。
2. **VR Vlog → lilToon VRM 1.0を書き出す** を開きます。
3. **アバター** にHierarchyのアバター最上位を指定し、**作者名** を入力します。
4. **保存先を選んでVRMを書き出す** を押します。

出力する画像は、標準VRM表示・lilToon専用表示ともに縦横比を保って最大1024×1024へ縮小します。小さい画像は拡大しません。元のアバターや画像は変更せず、縮小した画像を結果に表示します。更新の効果を得るには、元アバターからVRMを書き出し直してください。

正常に書き出せた場合は、そのまま保存され、書き出し画面内に完了を表示します。完了ダイアログを閉じる操作は不要です。保存先は必要なときに **保存先を開く** から確認できます。対策画面は実際に書き出しが失敗した場合に表示します。

### iPhoneで読み込む

1. 書き出した `.vrm` をiPhoneの「ファイル」に保存します。
2. VR Vlogの設定で **lilToon専用表示** をオンにします。
3. **モデルを変更 → 端末のVRMを選ぶ** からファイルを選びます。表示設定を変更した場合は読み込み直してください。

### 瞬きを調整する

**書き出し設定 → 瞬き → 確認・調整** で、画面内に設定欄が開きます。自動で閉眼用の変形を確定できない場合は、**手動で閉眼を設定** を押し、アバター内のメッシュと閉眼用の変形を選んでください。大文字・小文字だけが違う名前も、選択した名前をそのまま使います。適用量を調整し、**開閉をプレビュー** で両目と必要な左右の動作を確認してから書き出してください。

表情の取り込みと体のポーズの取り込みは別々に判定します。`trackingLeftHand` などを含む **ポーズ未対応** は、体の固定ポーズを確定できないという診断です。顔の表情の件数は、書き出し結果の **VRChatから追加できた表情** で確認できます。連続調整のPuppetを一つの固定表情に変換することはできません。

顔の表情は、外部入力を一定の書き出し条件に置き換えて、選んだ結果を固定表情として保存します。VRChatの入力による自動切り替えはアプリへ持ち込みません。ステーション外・非AFK・無音・手のジェスチャーなしなどの通常状態を使い、接触・PhysBoneのパラメーターにはアバターに設定された初期値を使います。通常メニュー、ジェスチャー、FaceEmoに同じ固定条件を使い、メニューで選んだ値と、対応するParameter Driverの動作も評価します。直接クリップは元のレイヤー順・重みで常時設定と合成します。使った外部入力の値は書き出し結果に表示します。

ジェスチャー・FaceEmoの直接クリップでは、対応する状態・クリップを確認でき、Parameter Driverが有限の値を`Set`する場合、その設定も評価します。同じクリップを使う複数の状態が同じ`Set`設定を持つ場合も取り込めます。処理でFaceEmoのクリップが置き換わる場合は、NDMFが記録した参照から登録元との対応を一意に確認します。名前や曲線の一致だけでは対応を決めません。必要な値に影響する`Add`・`Copy`・`Random`、状態との対応や設定が一致しないDriver、状態マシン全体のDriverは、初期値で代用せず診断します。

手動表情のFX状態で、Floatパラメーターが直接クリップの正規化再生位置（[Motion Time](https://docs.unity3d.com/2022.3/Documentation/ScriptReference/Animations.AnimatorState-timeParameterActive.html)）を固定している場合は、BlendShapeの曲線が一定でなくても、その位置の静止表情を取り込みます。全Controllerと省略するDriverの書き込みを検査し、値が変わらず実際の評価値とも一致すると確認できる場合に限ります。初期値が異なっていても、全書き込みが同じ有限の`Set`値のみで、実際の評価値がその値へ到達済みなら、以後の再生位置が固定されることを確認します。この確認値を初期値や状態の到達判定には使いません。時間経過で動く表情、到達可能な時間付き遷移、再生位置が未確定のBlendTreeや状態設定の検査は維持します。

表情から独立していると確認できた補助オブジェクトの表示・Transformアニメーションは、一時コピーで評価しますがVRM表情には保存せず、警告に表示します。実際の表情値と処理後の基準形の差分から、変形する頂点とそれに影響するボーンを確認します。選択表情のレイヤー、対象Rendererの表示・配置、変形する頂点に影響するボーンの変更は、この省略の対象外です。影響範囲の確認が終わるまで、その表情の書き出し用変形を生成しません。数値や参照が不正な場合、または影響範囲を確認できない場合の検査は維持します。

手動表情として保存するBlendShapeは、選択した表情と、そのパラメーターから動く表情を起点に判定します。同じRendererの初期値・リセット・下位レイヤーの合成も保持します。評価用のFXには衣装などの独立した動作も残しますが、それらの古いBlendShape参照だけで顔の取り込みを止めません。選択した表情や、その結果に影響する顔の出力先が失われている場合は、引き続き対象を診断します。

体のポーズは別に判定します。型と初期値が一致し、Driverや曲線に書き換えられない入力から、到達しない状態を確認して表情の依存範囲を絞ります。メニューのオフ・初期値を選ぶ表情も保持します。同じ固定条件で到達しない時間付き遷移や、表情を支える下位レイヤーの未到達状態にある移動・オブジェクト差し替え・イベントだけを理由に、表情を省略しません。FX全体を無効にする状態やFX以外のPlayable Layerによる必要なパラメーターの変更が書き出し条件から到達可能な場合、不明なBehaviour、Random、静止しない表情などは引き続き理由付きで省略します。直接クリップのために省略したDriverが他の表情へ影響する場合も、初期値を決めつけず診断します。実値を決められない目の高さ（`EyeHeightAsMeters`・`EyeHeightAsPercent`）が必要な表情も、Controllerの初期値で代用せず省略します。原本のController・メッシュ・設定は変更せず、一時コピーで評価します。書き出し用コピーは元シーンとは別の専用シーンで処理・破棄し、元シーンの変更済み状態と選択中シーンを保持します。親の移動・回転・非均等スケールがあるアバターでも、従来の書き出し用コピーと同じ位置・回転・スケールを使います。

## 対応範囲と制限

- FXのデフォルト状態で設定される顔・体形のシェイプキーも、安定した初期状態を確認してVRMの基準形に保存します。表情をデフォルトに戻したときもこの形を維持します。AAOの最適化を併用しても、焼き込み済みの初期表情を二重に適用しないよう保護します。時間や外部入力、未対応のFX構成により基準形を確定できない範囲は、対象と理由を警告に表示し、処理後のアバターに設定されている値を保持して書き出しを続けます。影響が独立している安定した設定は引き続き反映します。不正な数値や壊れた参照、最適化による必要な設定の喪失は書き出しを停止します。
- 以前の書き出しで目が閉じたままになるなど基準形が失われていた場合は、更新したExporterで元Unityアバターから再書き出し、VR Vlogで読み込み直してください。失われた設定を既存VRMだけから推測して復元することはできません。

- Unified Expressions の既知のシェイプ名を持つ顔メッシュは自動で検出し、`UE/<項目名>` の連続値カスタム表情へ書き出します。全部の項目がなくても利用できます。通常の ARKit と共通の名前だけでは自動判定しません。利用には対応版の VR Vlog が必要です。UE の追跡用モーフが残っている既存のローカル VRM はアプリで補完できます。モーフが失われている場合や新しい設定を出力する場合は、元アバターから再書き出してください。
- 既存の追跡設定コンポーネントと VRM の手動設定を優先します。項目名の重複は書き出し結果に表示し、あいまいな割り当てを省略します。アプリで反映できる動きは iPhone の顔トラッキングで取得できる範囲です。舌の向き・頬吸いなどの未取得信号や、VRChat の Animator だけで実現するギミックは再現しません。
- 追跡設定コンポーネントを付けたアバターでは、ARKit標準名52項目をVRM 1.0のカスタム表情へ書き出せます。この52項目は明示的な設定がある場合に書き出します。設定がなくても UE の既知のシェイプ名があれば、UE 表情を自動登録します。Kipfel用の設定とPrefabは別配布の顔トラッキングアドオンから導入してください。
- lilToonの見た目、対応する顔・体形の調整、VRChat・FaceEmoの表情、Modular Avatarで設定した髪・衣装を引き継ぎます。
- NDMFの最適化処理を含めて書き出すため、Avatar Optimizerのマスクや **AAO Remove Mesh By Box** によるメッシュ削除と、外部ツールで差し替えた削除済みメッシュを反映します。Boxは衣装などのRendererに設定したAAOの範囲を使い、通常のBoxColliderを置くだけではメッシュを削除しません。AAOのプレビューで削除範囲を確認してから、元アバターからVRMを書き出し直してください。Avatar Optimizerは任意依存で、公式連携APIのある1.7以上・2.0未満に対応します。必要な表情や材質参照が最適化で失われた場合は書き出しを停止します。
- AAO 1.9.20本体の頂点バッファ解放漏れには、[同版用の明示的な修正パッチ](Documentation~/DependencyPatches/README.md)を同梱しています。元の共有パッケージを保持したコピーへ、版とソースの一致を確認して適用します。検証結果には「1.9.20 + 修正パッチ」と記録し、エクスポート中の自動書き換えは行いません。
- Modular Avatar統合後のFXにある、パラメーターに依存しない静止BlendShapeレイヤーを通常状態と対応する表情へ適用します。時間変化やBehaviourで制御する常時効果は自動判定しません。常時設定と合成する直接クリップがAdditiveレイヤーにある場合は、その表情を未対応として表示します。
- 導入済みVRChat SDKのPhysBoneを、髪・衣装のVRM SpringBoneへ変換します。力・減衰・重力は近似です。書き出し結果に件数と未対応項目を表示します。[揺れ物変換の詳細](Compatibility/PhysBone.md)
- すべてのシェーダー効果・表情・VRChatの動作を再現するものではありません。外部連携や独自改造シェーダー、任意のギミック全般の変換は対象外です。
- 髪や衣装には、元のUnityプロジェクトで接続設定が必要です。非表示の衣装は出力されません。
- 他のVRMビューアーでは標準MToonによる互換表示になり、見た目や動く表情が異なる場合があります。
- モデルによっては端末のメモリ不足で読み込めない場合があります。

## 困ったとき

**VR Vlog → 動作環境を確認** で、必要なパッケージと現在のバージョンを確認できます。
未対応版の場合は書き出しを停止し、対処方法を表示します。パッケージを自動で変更することはありません。
今後の更新への対応手順は [互換性の管理](Compatibility/README.md) を参照してください。

書き出し結果の **書き出しの詳細** で対象と対処方法を確認してください。解決しない場合は、バージョン・再現手順・該当エラーを添えて [Issues](https://github.com/mitsuya0077/VR-Vlog-lilToon-Exporter/issues/new/choose) へ報告できます。

### コピーで対策を試す

書き出しが止まった場合、エラー画面に **工程・対象・原因・対策・失われる効果** を表示します。確認できた問題にだけ対策候補を付けます。未知のギミックやオブジェクト名だけを根拠に削除を勧めることはありません。

1. 対象と影響を読み、試す対策を選びます。初期の対策は、該当材質のAudioLinkをOFF、メインカラー2nd／3rdレイヤーを省略、作者が代替表示で隠す指定をした補助Rendererの除外です。
2. 選んだ対策を試します。毎回、元アバターから新しいコピーを作ります。共有マテリアルを使う対象では、コピー内の同じ材質を使う箇所すべてへ対策が適用されます。
3. 比較画面の **書き出すVRM** で、実際に生成・再読み込みしたVRMを確認します。必要に応じて対策前後の入力コピーも比較できます。VRMのプレビューは **標準MToon表示** です。iPhoneのlilToon専用表示は端末で別途確認してください。
4. 対策を選んだ場合は、見た目を確認してから明示的に保存します。設定を変えずに再試行して成功した場合は自動保存し、保存先にファイルがあれば上書きを再確認します。上書きを断ると保存しません。対策を解除すると元設定からやり直せます。

原本や参照アセットを編集した場合、以前の診断・プレビューを使って保存せず、再検査します。再試行が失敗しても直前の成功結果と保存済みVRMは保持します。未知シェーダー・外部参照・不正PhysBoneは対象と手動での対処を案内し、衣装・髪・骨格を一括除外しません。

不具合報告には共有用の診断をコピーできます。共有用の内容は工程・エラーの種類・対策の種類を中心とし、アバター名・材質名・絶対パス・画像・元のスタックトレースを含めません。

VR Vlogアプリ内の問い合わせからもご連絡いただけます。
