# 多様なアバターの書き出しと見た目の保持

アバター名・販売モデル・特定ボーン名を条件にせず、準備後の実際の参照・階層・描画内容から変換します。
原本を編集せず、MA / NDMFが解決した衣装・骨格・材質と、評価できる基準形を出力用コピーに保持します。
「書き出せた」だけでは成功とせず、保存したVRMを再読込して形状・表情・揺れ設定を検証します。

## 自動で続行する場合

| 構成 | 保存方法 | 変化する範囲 |
| --- | --- | --- |
| 親子・同じRoot・一部だけが重なるPhysBone | 関節ごとに既存VRM、より局所のRoot、同Root上のコンポーネント、階層・コンポーネント順を優先。境界は専用末端で分ける | 静止姿勢・骨格・境界の長さを保持。重複していた揺れはVRM向けの近似となり、対象と方針を表示 |
| PhysBoneの同位置の区間 | 駆動のない区間だけ省き、有効な連鎖と元の深度に応じた力を残す | 元のボーンとスキニングは残す。省略した区間を表示 |
| 左右の閉眼が別のメッシュにある | 既知の同じ名前系列で左右がそろうことを確認し、両目・片目の瞬きを登録 | 元の変形量と左右の独立性を保持 |
| 最適化や削除処理で描画が空になったメッシュ | UniVRMが出力しない描画ゼロのメッシュを専用材質の結び付けから外す。瞬きなし用の空表情は描画がある対象へ置く | オブジェクト・ボーン・他の描画を削除しない |
| 無効なlilToonの2nd/3rdレイヤーに残った保存不能な画像 | 公式シェーダーのフラグ・キーワードと、元/準備後の材質変更の有無から未使用と証明できる参照だけ省く | 現在の材質値は保持。通常の保存可能な画像は無効レイヤーでも保存 |
| Unityが初回参照時に作る曲線・材質の内部キャッシュ | 読み取りAPIでキャッシュを確定してから変更検査の基準を作る | キャッシュ作成だけでは再試行を拒否しない。実際の曲線・値・参照・保存設定の変更検査は維持 |
| FXの動的な基準形 | 独立して確定できる常時設定は評価し、確定できない変形は準備後の値を保持 | 保持した対象を表示。VRChat起動後の見た目とは異なる場合がある |

PhysBoneとVRM SpringBoneは異なる物理演算です。静止状態を保つことと、VRChatでの揺れ方を完全に再現することは別です。
変換の詳細は[PhysBoneの対応範囲](PhysBone.md)に記載しています。

## 形状を失わせないための検査

非有限値、アバター外への必要な参照、解決できない必須表情、出力から失われた変形・材質・揺れ設定を、
「続行できる」ことだけを目的に黙って削除しません。代替状態の正しさが証明できない処理は対象と理由を表示します。
未使用画像の判定でも、材質アニメーション・差し替え・PropertyBlock・不明なイベント等がある場合は推測しません。

同じ形に見えるメニュー表情でも別の変形ターゲットを維持します。ターゲットを共有すると、複数表情を同時に使った際の
適用量の制限や合算が変わるビューアーがあるためです。メモリの制限を回避するために表情を削る処理は行いません。

## 回帰検証

PhysBoneの親子・同Root・部分重複・既存VRM・分岐・末端・コライダー・ゼロ長、左右別メッシュの瞬き、
描画ゼロのMesh/SkinnedMeshRenderer、lilToon/マルチの有効状態、原本の変更検査を組み合わせて検証します。
標準VRMと専用lilToon出力を再読込し、静止状態、表情0→1→0、両目/片目、表情の重ね掛け、揺れの追従・収束を確認します。
これらは任意の追加スクリプトや全ビューアーの完全な互換性を保証するものではありません。
