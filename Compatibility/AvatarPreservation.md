# 多様なアバターの書き出しと見た目の保持

アバター名・販売モデル・特定ボーン名を条件にせず、準備後の実際の参照・階層・描画内容から変換します。
原本を編集せず、MA / NDMFが解決した衣装・骨格・材質と、評価できる基準形を出力用コピーに保持します。
「書き出せた」だけでは成功とせず、保存したVRMを再読込して形状・表情・揺れ設定を検証します。

## 自動で続行する場合

| 構成 | 保存方法 | 変化する範囲 |
| --- | --- | --- |
| 親子・同じRoot・一部だけが重なるPhysBone | 関節ごとに既存VRM、より局所のRoot、同Root上のコンポーネント、階層・コンポーネント順を優先。境界は専用末端で分ける | 静止姿勢・骨格・境界の長さを保持。重複していた揺れはVRM向けの近似となり、対象と方針を表示 |
| PhysBoneの同位置の区間 | 駆動のない区間だけ省き、有効な連鎖と元の深度に応じた力を残す | 元のボーンとスキニングは残す。省略した区間を表示 |
| 左右の閉眼が別のメッシュにある | 既知の同じ名前系列で左右がそろうことを確認し、両目・片目の瞬きを登録 | 元の変形量と左右の独立性を保持 |
| 最適化や削除処理で描画が空になったメッシュ | UniVRMが出力しない描画ゼロのメッシュを専用材質の結び付けから外す。瞬きなし用の空表情は描画がある対象へ置く | オブジェクト・ボーン・他の描画を削除しない |
| UV0のないメッシュ | 出力用データだけに頂点数分の `(0, 0)` を補う | 元の形状・表情・スキニングを保持。既存のUV0は変更せず、補完した対象を表示 |
| 法線のないメッシュ | 書き出し専用のメッシュコピーの三角形から法線を補う。方向を生成できない頂点だけ一定軸で近似 | 既存の法線は再計算しない。補完した対象と近似を表示し、陰影をプレビューで確認 |
| MeshRendererの追加頂点ストリーム | 実際に上書きされる形状・UV・法線などをRendererごとに書き出し専用のコピーへ合成 | 同じメッシュを共有していても各Rendererの描画を個別に保持。元のメッシュと追加ストリームを変更しない |
| 無効なlilToonの2nd/3rdレイヤーに残った保存不能な画像 | 公式シェーダーのフラグ・キーワードと、元/準備後の材質変更の有無から未使用と証明できる参照だけ省く | 現在の材質値は保持。通常の保存可能な画像は無効レイヤーでも保存 |
| Unityが初回参照時に作る曲線・材質の内部キャッシュ | 読み取りAPIでキャッシュを確定してから変更検査の基準を作る | キャッシュ作成だけでは再試行を拒否しない。実際の曲線・値・参照・保存設定の変更検査は維持 |
| FXの動的な基準形 | 独立して確定できる常時設定は評価し、確定できない変形は準備後の値を保持 | 保持した対象を表示。VRChat起動後の見た目とは異なる場合がある |

PhysBoneとVRM SpringBoneは異なる物理演算です。静止状態を保つことと、VRChatでの揺れ方を完全に再現することは別です。
変換の詳細は[PhysBoneの対応範囲](PhysBone.md)に記載しています。

## UV0・法線の欠落

UniVRM 0.131.0のモデル変換は、頂点数と一致するUV0・法線だけを中間データに登録します。一方、
VRMを書き込む処理は両方が存在することを前提に参照するため、UV0がないメッシュでは
`MeshWriter.ExportMeshDivided` で `NullReferenceException` が発生します。法線の欠落でも同じ前提が問題になります。

書き出し用データに限って欠けた属性を補い、元のアバター、共有メッシュ、依存パッケージは編集しません。
MeshRendererの `additionalVertexStreams` が属性を供給している場合は、その実効値を優先して
書き出し専用のコピーへ合成します。元のメッシュにUV0や法線がないだけで欠落と判定せず、
追加ストリームを合成しても残る欠落だけを補います。
UV0にはUnityの座標系で各頂点の `(0, 0)` を使い、UniVRMが座標を変換する前に中間データへ追加します。
UV1など他のチャンネルは流用せず、失われたUV配置を推測・復元する処理でもありません。
法線がない場合は一時メッシュの `RecalculateNormals` で三角形から法線を作ります。
縮退した面などで新たに生成した法線が有限のゼロベクトルになる頂点だけは、Unity座標系の `+Z` で近似し、
対象と近似した内容を表示します。形状やモーフを削除する処理ではありません。非有限の法線が生成された場合は
エラーにし、既存の法線をこの近似で上書きすることもありません。
このコピーはUniVRMのモデル変換から専用材質の結び付け・VRM書き込みまで保持し、実効UVも専用出力へ保存します。
結び付けには共有メッシュだけでなく各Rendererの変換先ノードを使い、同じメッシュに異なる追加ストリームを使う構成を区別します。
書き出し終了時は成功・失敗にかかわらずRendererのメッシュ参照・追加ストリームを元に戻し、一時メッシュを破棄します。
元の頂点・法線・UV・表情の配列は書き換えず、元々あった法線は再計算しません。
法線のない形状から作者が調整した陰影までは復元できないため、補完した対象と内容を表示し、
書き出したVRMのプレビューで陰影を確認してください。欠落と不正なデータは区別し、既存の属性を上書きして隠しません。

## 形状を失わせないための検査

非有限値、アバター外への必要な参照、解決できない必須表情、出力から失われた変形・材質・揺れ設定を、
「続行できる」ことだけを目的に黙って削除しません。代替状態の正しさが証明できない処理は対象と理由を表示します。
未使用画像の判定でも、材質アニメーション・差し替え・PropertyBlock・不明なイベント等がある場合は推測しません。

同じ形に見えるメニュー表情でも別の変形ターゲットを維持します。ターゲットを共有すると、複数表情を同時に使った際の
適用量の制限や合算が変わるビューアーがあるためです。メモリの制限を回避するために表情を削る処理は行いません。

## 回帰検証

PhysBoneの親子・同Root・部分重複・既存VRM・分岐・末端・コライダー・ゼロ長、左右別メッシュの瞬き、
描画ゼロのMesh/SkinnedMeshRenderer、UV0・法線の欠落と既存属性の保持、縮退面の法線近似、追加頂点ストリームによる上書き、
lilToon/マルチの有効状態、原本の変更検査を組み合わせて検証します。
標準VRMと専用lilToon出力を再読込し、静止状態、表情0→1→0、両目/片目、表情の重ね掛け、揺れの追従・収束を確認します。
これらは任意の追加スクリプトや全ビューアーの完全な互換性を保証するものではありません。
